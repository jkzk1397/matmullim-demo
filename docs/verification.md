# 맞물림 검증 기록

맞물림이 짚는 오류가 맞는지(정밀도), 그리고 오류를 놓치지 않는지(재현율)를 실제 공개 문서로 잰 기록이다.
원본 문서와 학교 이름은 저장소에 넣지 않는다. 문서는 학교알리미에 공시된 경기도 중학교 「교과별(학년별) 평가계획」이다.

## 데이터

| 묶음 | 문서 | 용도 |
|---|---|---|
| 개발 묶음 | 2024~2026학년도 595개(같은 문서 중복 제외 591개), 2026학년도 88개(개발 묶음과 87개 겹침) | 규칙을 만들고 고치는 데 사용 |
| 처음 보는 묶음 | 2026학년도 1·2학기 전 교과 320개(66개 학교, 무작위 표집) | 규칙을 고정(커밋 `0a778fd`)한 뒤 한 번만 평가. 개발 묶음과 내용이 겹치는 문서 0개(6어절 단위 비교) |

## 1. 짚은 것이 맞는가 (원문 대조)

빨강(확인된 오류)·주황(지침과 다름) 카드마다 문서에서 해당 칸의 원문을 다시 뽑아(스크립트) 한 건씩 대조했다.

| 묶음 | 대조한 카드 | 실제 오류 | 오판 | 판단이 갈림 |
|---|---|---|---|---|
| 개발 묶음 (현재 규칙) | 92 | 91 | 0 | 1 (채점기준의 ‘분량’ 표현) |
| 처음 보는 묶음 (고정 규칙) | 156 (빨강 106, 주황 50) | 126 (빨강 98 = 92.5%) | 25 | 5 |
| 처음 보는 묶음 (원인 수정 후) | 130 | 126 | 0 | 4 |

- 개발 묶음 검증 중 오판 4건(체육·예술 논술형 기준을 다른 교과에 적용 3건, 코드–문장 짝 1건)을 찾아 고쳤다.
- 처음 보는 묶음의 오판 25건 원인: 병합된 표 머리글 줄을 영역 이름으로 읽어 수행평가를 정기시험으로 셈(수행평가 비율 16건), 만점 대조 6건(괄호 안 하위 배점 “20점(논술형 5점)” 3건, “1·2차 각 25점” 1건, 병합 칸 복사로 같은 이름 칸 중복 1건, 세부기준 병합 칸의 연속 줄 1건), 안내문(※)이 든 칸을 통째로 뺌 1건, 기호(•)뿐인 논술형 비율 칸 1건, 식품의 ‘1인 1회 분량’ 1건. 판단이 갈림 5건 중 1건은 고입 내신용 보조 표였다. 모두 고친 뒤 다시 돌려 오판 카드가 사라지고 실제 오류 카드는 그대로인 것을 확인했다.
- 확인된 오류가 하나 이상 있는 문서: 개발 묶음 591개 중 51개, 처음 보는 묶음 320개 중 54개 → 911개 중 105개.
- 처음 보는 묶음의 실제 오류 126건 종류: 성취기준 코드 표기 63(괄호 빠짐 42, 코드 오타 13, 없는 코드 6, 다른 교육과정 접두어 2), 성취기준 문장 49(학년도·학년으로 정한 적용 교육과정이 아닌 다른 교육과정의 같은 코드 문장 29, 같은 교육과정의 다른 코드 문장 20), 채점기준 표현 8, 반영비율 합계·만점 5, 논술형 반영비율 1.

## 2. 놓치지 않는가 (오류 주입)

실제 문서에 알려진 오류를 하나씩 넣고 맞물림이 찾는지 잰다. `scripts/inject-eval.ts`.

| 오류 종류 | 처음 보는 묶음 (고정 규칙) |
|---|---|
| 성취기준 번호 오기 | 376 / 376 |
| 성취기준 교과 글자 오타 | 399 / 399 |
| 반영비율 합계 오류 | 334 / 339 |
| 만점·배점 불일치 | 243 / 244 |
| 논술형 반영비율 미달 (경기 2026 지침) | 256 / 256 |
| 결시자 처리기준 누락 | 358 / 358 |
| 지양 표현(제출 여부) | 223 / 224 |
| **전체** | **2,189 / 2,196 (99.7%)** |

개발 묶음(현재 규칙): 1,490 / 1,495 (99.7%). 2026학년도 88개: 384 / 384.

한계: 주입한 오류는 팀이 만든 7가지 유형이다. 실제 문서에서 아직 모르는 유형의 오류를 놓치는 비율은 이 방법으로 잴 수 없다.

### 학년 수행평가 달력

처음 보는 묶음 320개 중 표를 읽는 HWP·HWPX 207개에서(PDF 113개는 표를 읽지 않아 뺐다), 전 교과가 한 파일에 든 계획서로 학년·학기를 알고 교과가 8개 이상인 학년 달력 22개(17개교, 모두 2026학년도)를 만들었다. 요약표 ‘평가 시기’ 칸을 읽고, 주마다 수행평가가 있는 교과 수를 센다(같은 교과의 평가 여러 개는 한 교과).

| 한 주에 수행평가를 둔 교과 수(가장 많은 주) | 5개 이상 | 4개 이상 |
|---|---|---|
| 그 주 하나로 적은 평가만 셈 | 22개 중 9개 | 22개 중 11개 |
| 두 주 안으로 적은 평가까지 셈 | 22개 중 11개 | 22개 중 18개 |
| 여러 주에 걸친 평가를 걸친 주마다 셈 (앱 달력) | 22개 중 15개 | 22개 중 21개 |

가장 많이 몰린 곳은 3학년 1학기 4월 1주로, 11개 교과 중 10개 교과가 수행평가를 그 주로 적었다.

포스터는 가운데 줄(두 주 안으로 적은 평가까지 셈)과 5개 교과 이상을 쓴다: 22개 중 11개. 앱 달력도 교과 수를 세고, 기본으로 5개 교과 이상인 주를 빨갛게 표시한다(3·4·5개 중 고를 수 있음). 지침에는 몇 개부터 많은지 정한 수치가 없다.

### 한꺼번에 읽기

앱(헤드리스 크롬, 2코어 가상 머신)에 처음 보는 묶음 320개를 한꺼번에 끌어 놓으면 109.6~112초에 교과 658개 구간을 점검한다. 처음에는 끝무렵 탭이 멈췄는데, PDF 문서를 읽은 뒤 정리하고(pdf.js `destroy`) 고친 파일을 다시 쓸 일이 없는 형식(HWP·PDF 등)은 원본 바이트를 들고 있지 않게 바꿔 해결했다.

## 다시 돌리기

```
npx tsx scripts/eval-docs.ts docs.json 결과.json      # 문서별 카드
npx tsx scripts/inject-eval.ts docs.json 결과.json    # 오류 주입 재현율
```
`docs.json`은 문서를 표로 읽어 둔 배열이다(형식은 스크립트 머리 주석). 원본 문서는 학교알리미에서 받는다.
