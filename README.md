# 「맞물림」 데모 — 교·수·평 정렬 사전 점검

평가계획서와 수행평가 채점기준표, 두 HWPX 문서를 올리면 **문서 사이의 불일치**를 근거와 함께 보여 주고,
고친 문서를 다시 올리면 무엇이 **해결됐는지** 비교해 보여 주는 공모전 발표용 작동 데모입니다.

- 대상: **2022 개정 교육과정 · 중학교 정보** 문서 하나
- 모든 처리는 **브라우저 안에서** 이뤄지고 서버로 보내지 않습니다 (백엔드 없음, LLM 호출 없음)
- 화면의 카드는 하드코딩이 아니라 **HWPX 파싱 → 표 머리글로 값 추출 → 결정적 규칙 계산**에서 나옵니다

## 실행 방법

```bash
npm install
npm run dev          # http://localhost:5173
npm test             # vitest (규칙·파서 테스트 21개)
npm run build        # dist/
npm run samples      # src/fixtures → public/samples/*.hwpx 다시 만들기
npm run build && npm run screenshots   # screenshots/*.png 6장 다시 찍기 (1366×768 @2x, Playwright)
```

GitHub Pages: `.github/workflows/pages.yml`이 `main`과 `claude/demo-creation-skev7t` 푸시 때 테스트 → 빌드 → 배포합니다.
처음 한 번은 저장소 **Settings → Pages → Source를 “GitHub Actions”**로 바꿔야 합니다. `github-pages` 환경의 브랜치 보호 규칙이
기본 브랜치만 허용하면, 작업 브랜치를 `main`에 합친 뒤 배포됩니다. 배포 주소는 `https://<계정>.github.io/matmullim-demo/`입니다.

## 디자인

- 로고: `public/brand/`(마크·전체 로고·파비콘). 상단 바 왼쪽에 마크와 “맞물림”을 두고, 로고의 남색을 주 버튼·현재 단계에, 초록을 “해결됨”·통과 표시에 씁니다.
- 발표 스크린샷 기준: 내용 최대 폭 1240px, 흰 상단 바, 글자 크기 4단계(30·20·17·14px), 옅은 그림자 하나, 8px 간격.
- 카드 색은 진한 점이나 왼쪽 4px 테두리와 같은 색 글자 라벨로만 씁니다: 빨강 확인된 오류, 주황 지침 권고와 다름, 회색 연결 확인 필요, 노랑 제안.
- 결과 화면은 지적마다 내 문서와 대조 문서(다른 문서·성취기준 DB·교육청 지침)를 나란히 보여 주고, 다른 값만 강조합니다.
- ‘고치기’는 앱 안에서 값을 바꾸는 게 아니라 문서를 고쳐 다시 올리는 흐름입니다. 확인 화면에서 바꾼 값은 결과에 ‘교사가 고친 값으로 점검’으로 표시됩니다.
- 디자인 과정은 [impeccable](https://github.com/pbakaus/impeccable) 스킬(`.claude/skills/impeccable`)로 진행했고, 기록은 `PRODUCT.md`, `DESIGN.md`, `.impeccable/`에 있습니다.

## 범위

| 만든 것 | 내용 |
|---|---|
| HWPX 파서 | JSZip으로 `Contents/section*.xml`을 열어 `hp:tbl → hp:tr → hp:tc` 셀 텍스트를 2차원 배열로. `cellAddr`·`cellSpan`으로 병합 최소 처리 |
| 추출 | 표 첫 행 머리글 낱말로 칸의 뜻을 정함 (`docs/hwpx-template.md`) |
| 교사 확인 | 추출값 수정, 두 문서 평가 짝짓기, 확인 시간 기록. 확인한 값만 점검에 씀 |
| J12 문서 간 불일치 | 빨강: 짝지은 평가의 만점 ≠ 채점기준표 배점 합계, 반영비율 합계 ≠ 100%. 회색: 평가요소 이름·개수 다름, 성취기준 목록 불일치, 짝 없음 |
| J4 코드 확인 | `[9정DD-DD]` 형식인데 DB에 없으면 빨강. 다른 교과·교육과정 코드는 회색 “현재 지원 범위(2022 개정 중학교 정보)에서 확인 불가” |
| J7 채점기준 표현 | 수행률(%)·분량(쪽·장·글자 이상)·감점·지적 횟수·출석률 표현이 있으면 주황. 경기도교육청 원문 문장과 “학교 학업성적관리규정도 확인하세요” 표시 |
| J6 정렬 확인 | 계획의 학기 성취기준 중 어떤 평가와도 연결되지 않은 것은 회색. 교사가 정렬 맵에서 연결을 지정하면 사라짐. 교육적 타당성은 판정하지 않음 |
| 노랑 제안 1개 | S5 학생 성찰 기회: 채점기준표에 성찰·자기평가·동료평가 요소가 없으면 질문으로 제안 |
| 재점검 비교 | 카드의 안정 키로 이전 실행과 비교 |

모든 카드에는 **원문 위치(문서 › 표 › 평가 › 칸 경로와 칠한 원문 칸)**, **근거(규칙 출처와 원문 문장)**, **강도(사실·의무·권고·제안)**, **교사 행동(고치기·메모하고 넘기기·연결 지정)**이 들어갑니다.

## 실제 HWPX 파싱이 되는지

- **된다(최소 구조 기준):** `src/domain/hwpx.ts`가 zip 안의 `Contents/section*.xml`을 열어 표를 읽습니다. 예시 불러오기 버튼은 JSON이 아니라 `public/samples/*.hwpx`를 브라우저에서 실제로 파싱합니다(실패할 때만 JSON fixture로 대체).
- 테스트: fixture → HWPX 작성 → 다시 파싱하면 fixture와 같음(6개 문서), 커밋된 HWPX 파일 파싱, `cellAddr`가 없는 표의 병합 위치 계산.
- **확인하지 못한 것:** 예시 HWPX는 이 저장소의 작성기(`src/domain/hwpx-writer.ts`)가 만든 최소 구조라, 한글에서 열리는지와 한글이 저장한 실제 HWPX(문단 속성·캡션·중첩 표 등이 많은 파일)를 문제없이 읽는지는 확인하지 못했습니다. 한글로 `docs/hwpx-template.md` 형식의 표를 만들어 올려 보고 결과를 알려 주세요.

## 정한 것 (설계서·요청과 다르거나 빈 곳)

- **데이터 모델에 선택 필드를 더했습니다.** 요청한 `Assessment` 필드는 그대로 두고, 원문 칸 하이라이트와 카드 위치를 위해 `method`(평가 방법), `refs`(값별 원문 칸), `elements[].rubricText`, `elements[].refs`를 추가했습니다. 만점(`maxScore`)·배점(`points`)·반영비율(`weightPercent`)은 서로 다른 필드이며 규칙에서 섞지 않습니다.
- **예시 fixture는 “파싱 결과 단계”(표 2차원 배열)** 로 넣었습니다(`src/fixtures/*/plan.json`, `rubric.json`). 그래서 추출과 규칙이 모두 실제 코드로 돌고, 같은 fixture에서 HWPX도 만듭니다.
- **지필평가는 채점기준표 짝을 요구하지 않습니다.** 평가 방법에 `지필`이 있으면 짝 없음 회색 카드에서 제외합니다.
- **평가요소 배점 개별 차이**는 별도 카드로 띄우지 않고, J12 빨강 카드의 나란히 비교 표에서 강조합니다.
- **J4 범위:** 2015 개정 중학교 정보 코드도 `[9정DD-DD]` 형식이라 형식만으로는 구분할 수 없습니다. 그런 코드는 2022 DB에 있으면 통과, 없으면 빨강으로 봅니다.
- **회색 카드의 강도는 “사실”** 로 표시합니다(“문서에서 연결이 보이지 않는다”는 관찰은 사실이고, 결론은 교사에게 맡김).
- **J7 쪽수**는 요청대로 “인쇄 31쪽(중학교 예시) — 원문 대조 후 확정”으로 두었습니다. (설계서 v2 본문에는 28쪽으로 적혀 있어 원문 대조가 필요합니다.)
- **S5 제안**의 근거는 “2022 개정 교육과정 총론의 평가 방향”으로만 적고 원문 문장은 인용하지 않았습니다(문장을 확인하지 못해 지어내지 않음).
- **Pretendard 글꼴**은 CDN 대신 npm 패키지(`pretendard@1.3.9`)를 번들했습니다. 작업 환경에서 jsDelivr CDN이 막혀 있었고, 오프라인 발표장에서도 같은 화면이 나오게 하기 위해서입니다.
- **카드 정렬**은 색(빨강→주황→회색→노랑) 다음 규칙 순서(J12→J4→J7→J6→S5)입니다.
- **재점검 비교 키**는 규칙 + 평가명/코드로 만듭니다. 평가명을 바꾸면 다른 지적으로 봅니다.
